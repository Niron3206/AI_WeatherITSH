# 🌥️ AI_WeatherITSH

Модель предсказывает температуру воздуха на сутки вперёд по истории наблюдений. LSTM-сеть получает на вход семь дней почасовых замеров (давление, температура и третий канал) и выдаёт 144 значения температуры: по одному на каждые десять минут следующих суток.

Сеть обучалась на публичном датасете Jena Climate 2009–2016. Прогноз строится по показаниям любительских метеодатчиков: их отдаёт REST API narodmon.ru.

Проект написан в 2023 году, чтобы разобраться, как рекуррентные сети ведут себя на временных рядах. Учебная работа, а не сервис прогноза погоды. С тех пор он не обновлялся.

## Данные

**Обучение.** Jena Climate 2009–2016, записи метеостанции Института биогеохимии Макса Планка в Йене (Германия): 420 551 запись с интервалом 10 минут, 14 метеовеличин. Архив `model.py` скачивает сам из хранилища TensorFlow. Из 14 столбцов в модель пошли три: `p (mbar)`, `T (degC)` и `rho (g/m**3)`. Первые 300 000 записей идут на обучение, остаток на валидацию. Все три столбца приводятся к нулевому среднему и единичной дисперсии по статистикам обучающей части.

**Разбиение ряда на интервалы.** `intervals_organization.py` двигает окно по ряду на одну запись за шаг. В каждой позиции берёт предыдущие 1008 записей (ровно 7 дней) и прореживает их с шагом 6: остаётся 168 почасовых точек по 3 признака. Цель, которую сеть учится угадывать, следующие 144 значения температуры, то есть сутки вперёд в исходном десятиминутном разрешении.

**Прогноз.** Пакет `narodmonitoring` логинится в API narodmon.ru (`userLogon`) и запрашивает историю за месяц (`sensorsHistory`) по трём идентификаторам датчиков из `.env`: давление, температура, влажность. Всё это ложится в `csv_files/history_1month.csv`, а последние 168 строк отдельно в `csv_files/history_7days.csv`, они и уходят в модель. `forecast.py` стандартизует окно по его собственным среднему и отклонению, приводит к форме `(1, 168, 3)`, прогоняет через сеть и переводит результат обратно в градусы по статистикам температуры того же окна.

## Модель

Последовательная модель Keras:

| Слой | Параметры |
| --- | --- |
| LSTM | 32 нейрона, `return_sequences=True`, форма входа `(168, 3)` |
| LSTM | 16 нейронов, `activation='relu'` |
| Dense | 144 выхода, по одному на каждый десятиминутный шаг горизонта |

Оптимизатор RMSprop с `clipvalue=1.0`, функция потерь: средняя абсолютная ошибка. Учится 10 эпох по 200 шагов, батч 256, буфер перемешивания 10 000, 50 шагов валидации на эпоху. Зерно случайности зафиксировано: 13. Готовая модель сохраняется в формате SavedModel в `saved_model/AI_WeatherITSH-24H`. TensorFlow 2.11.1, Python 3.10.

## Ограничения

Сеть училась на одних данных, а применяется к другим. Обучение идёт по научной метеостанции в Йене, прогноз строится по любительским датчикам в Москве и области. Третий признак на входе тоже не совпадает: при обучении это плотность воздуха, при прогнозе влажность. Переживает ли модель такой переезд, осталось непроверенным.

Чисел качества здесь нет. При обучении отслеживалась только функция потерь.

Ещё две вещи бьют по точности на инференсе. Нормализация считается по статистикам самого входного окна, а не по сохранённым с обучения, поэтому одна и та же погода масштабируется по-разному в зависимости от недели. А истории трёх датчиков склеиваются просто по номеру строки, без выравнивания по времени и обработки пропусков; если API недоступен, скрипт останавливается.

Сегодня это стоило бы сделать иначе: держать один набор признаков на обучении и на прогнозе, сохранять скейлер вместе с моделью, замерить MAE на отложенном периоде против baseline и учить сеть на данных тех же датчиков, по которым потом строится прогноз.

## 🔧 Загрузка и настройка

1. Убедитесь, что у вас установлена версия Python `3.10.X` или выше.
2. Настройте себе среду (venv/conda и т.д. по вашему выбору) и установите все требования.
3. Скомпилируйте и обучите модель, просто запустив скрипт `model.py`. (Вы можете настроить модель по своему усмотрению, просто отредактируйте все необходимые переменные)

Готово... у вас есть обученная и полностью способная к прогнозированию модель.

#### И как мы предсказываем?

В проекте использован REST API с сайта `https://narodmon.ru`. Чтобы получить данные о погоде, вам необходимо изменить переменные среды в файле `narodmonitoring\.env`.
Прежде чем сделать это, вы должны создать там учетную запись и получить API ключ, логин и пароль.
Так же, найдите любую общедоступную точку с сенсорами давления, температуры и влажности, затем получите их идентификаторы и вставьте в файл `narodmonitoring\.env`.
Запустите `__init__.py`.

После того, как все будет сделано, запустите скрипт `forecast.py`, чтобы получить свой прогноз в виде визуализации матплота.
